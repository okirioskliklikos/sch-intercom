# Διαγνωστική δοκιμή ήχου Windows (Φάση 3, βήμα 1)

Το `tools/windows_audio_check.py` είναι **εργαλείο δοκιμής**, όχι κώδικας παραγωγής. Εκτελείται μία φορά σε Windows 10/11 από απλό λογαριασμό χρήστη, για να διαπιστώσουμε τι μπορεί να ελέγξει ο μελλοντικός Client χωρίς δικαιώματα διαχειριστή. Δεν αλλάζει τον Director, τον Client ή το πρωτόκολλο.

## Τι ελέγχει

1. **Ένταση και mute της προεπιλεγμένης εξόδου** (Core Audio μέσω `pycaw`): διαβάζει την τρέχουσα τιμή, ορίζει προσωρινά δοκιμαστική ένταση χωρίς mute και την επαναφέρει.
2. **Συνεδρίες ήχου εφαρμογών**: εμφανίζει ποιες εφαρμογές έχουν ήχο, σιγάζει όσες δεν ήταν ήδη σιγασμένες (εκτός από το ίδιο το script) και μετά ξεσιγάζει μόνο αυτές.
3. **Pause/Play media** (Windows System Media Transport Controls, το ίδιο σύστημα με τα κουμπιά play/pause στο παράθυρο έντασης των Windows): κάνει pause σε ό,τι παίζει και μετά play μόνο σε όσα σταμάτησε το script.

**Κανόνας επαναφοράς:** επαναφέρεται μόνο ό,τι άλλαξε το script και βρίσκεται ακόμη στην τιμή που όρισε. Αν ο χρήστης αλλάξει κάτι χειροκίνητα κατά τη δοκιμή (π.χ. ένταση, ξεσίγαση εφαρμογής, play/stop), το script δεν το αγγίζει και το καταγράφει στην αναφορά. Η επαναφορά γίνεται και με Ctrl+C.

Η αναφορά **δεν** περιέχει τίτλους τραγουδιών/βίντεο, μόνο ονόματα εφαρμογών.

## Εγκατάσταση (μόνο στον υπολογιστή δοκιμής)

Απαιτείται Python 3.10+ για Windows. Σε PowerShell ή Command Prompt, από τον φάκελο του repository:

```
py -m pip install pycaw comtypes psutil winrt-runtime winrt-Windows.Media.Control winrt-Windows.Foundation winrt-Windows.Foundation.Collections
```

Οι βιβλιοθήκες αυτές **δεν** προστίθενται στις εξαρτήσεις του `pyproject.toml`. Το script δέχεται και το παλαιότερο πακέτο `winsdk` αντί για `winrt-*`.

## Εκτέλεση

1. Βάλε να παίζει ήχος σε δύο τουλάχιστον εφαρμογές, π.χ. YouTube σε Chrome/Edge και Spotify.
2. Τρέξε:

   ```
   py tools\windows_audio_check.py
   ```

3. Μετά από κάθε αλλαγή το script ρωτά αν ακούστηκε (ν/ο). Όσο δεν απαντάς, η αλλαγή παραμένει, οπότε μπορείς στο μεταξύ να δοκιμάσεις και χειροκίνητη αλλαγή για να δεις ότι δεν αναιρείται.
4. Στο τέλος αποθηκεύεται αρχείο `windows_audio_check_<ημερομηνία>.txt` στον τρέχοντα φάκελο. Επικόλλησε το περιεχόμενό του στη συζήτηση.

Επιλογές:

- `--dry-run`: μόνο ανάγνωση, χωρίς καμία αλλαγή.
- `--test-volume 30`: δοκιμαστική ένταση σε % (αν είναι κοντά στην τρέχουσα, επιλέγεται άλλη).
- `--no-questions --hold-seconds 5`: χωρίς ερωτήσεις, κάθε αλλαγή κρατά 5 s.
- `--report αρχείο.txt`: όνομα αρχείου αναφοράς.
- `--ramp-ms 150`: η ένταση αλλάζει σταδιακά σε 150 ms αντί για απότομα, και η σίγαση εφαρμογής γίνεται χαμηλώνοντας πρώτα την ένταση της εφαρμογής στο 0. Με `--ramp-ms 0` γίνεται απότομα, όπως στην πρώτη έκδοση, για σύγκριση.

Σε Linux/macOS το script τερματίζει με μήνυμα (κωδικός 2). Οι έλεγχοι της λογικής επαναφοράς τρέχουν παντού με ψεύτικες συσκευές: `tests/test_windows_audio_check.py`.

## Τι θέλουμε να μάθουμε από την αναφορά

- Αν η ένταση/mute και η σίγαση ανά εφαρμογή λειτουργούν χωρίς διαχειριστή.
- Ποιες εφαρμογές εμφανίζονται στα Media Controls και ποιες δέχονται pause/play (π.χ. Chrome, Edge, Firefox, Spotify, VLC, Media Player).
- Αν μετά το play συνεχίζουν από το ίδιο σημείο.
- Ποια εκδοχή είναι καλύτερη για την ανακοίνωση: σίγαση εφαρμογών, pause media ή συνδυασμός (π.χ. pause όπου υποστηρίζεται και σίγαση για τα υπόλοιπα).

## Γνωστά όρια

- Τα Media Controls είναι προαιρετικά για κάθε εφαρμογή· όσες δεν τα υποστηρίζουν θα χρειαστούν σίγαση.
- Σε browsers, συνήθως μόνο ένα tab εμφανίζεται ως ενεργή συνεδρία media.
- Η ένταση των Windows δεν ταυτίζεται με τη φυσική ένταση εξωτερικών ηχείων.
- Δεν υπάρχει ακόμη αρχείο ανάκαμψης μετά από crash· αυτό αφορά την υλοποίηση στον Client (βήμα 2).
